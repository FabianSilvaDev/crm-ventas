Guía de uso del CRM de Ventas

Cómo usar la aplicación hoy, cómo funcionan los agentes de IA y desde qué punto partes.

📌 Estado actual del proyecto

El CRM está en Fase 1 (Cimientos). La interfaz ya tiene la estructura completa, pero solo una parte del backend está implementada: la gestión de leads. El resto de pantallas muestran datos de demostración etiquetados como Demo para que puedas validar el flujo visual mientras se construyen los endpoints.

1. Punto de partida: arrancar la app

1

Arranca el backend. Desde la raíz del repo:

corepack pnpm --filter @crm/api dev

Esto levanta apps/api en http://localhost:3000.

2

Arranca el frontend. En otra terminal:

corepack pnpm --filter @crm/web dev

La SPA se abre normalmente en http://localhost:4200.

3

Configura el token de desarrollo. El API usa autenticación de desarrollo con la cabecera X-Dev-Api-Token. Asegúrate de que tu .env tenga:

DEV_API_TOKEN=dev-local-token-no-es-un-secreto-real

El frontend ya envía este token automáticamente en cada llamada a LeadsApi.

⚠️ Importante

La pantalla /entrar aún no autentica contra un backend real. Para ver la interfaz, usa el botón "Ver demostración". Eso abre una sesión simulada (solo en desarrollo) que te permite navegar, pero no tiene credenciales reales.

2. Estructura de la aplicación

La navegación principal está arriba en escritorio y abajo en móvil. Estas son las 7 áreas mentales del producto:

🏠 Inicio

Centro de control: saludo, alertas, métricas y recomendaciones de IA. Muestra leads reales y datos de demostración.

🚀 Growth

Campañas, creativos, audiencias y experimentos. Hoy todo es Demo.

💼 Ventas

Leads, oportunidades, clientes y tareas de seguimiento. El conteo de leads y la tasa de respuesta son reales; el resto es demo.

🧩 Productos

Descubrir, analizar, puntuar y seleccionar productos. Hoy todo es Demo.

🤖 IA

Recomendaciones, historial de agentes y costos. Hoy todo es Demo.

📊 Analytics

Dashboard de revenue, margen, CAC, ROAS y embudo. Hoy todo es Demo.

⚙️ Configuración

Preferencias, conectores, marca y permisos. Hoy es principalmente estructura.

Todavía existen dos rutas legado con datos reales:

  • /leads — listado clásico de leads (funciona con el API real).
  • /sistema — estado de salud del API.

3. Lo primero que puedes hacer hoy: trabajar con leads

El flujo real empieza en Ventas o en /leads. El backend ya permite:

  • Ver la lista de leads paginada.
  • Ver la ficha de un lead.
  • Actualizar estado, notas y datos de contacto.
  • Marcar un lead como convertido.
  • Registrar la primera respuesta.

Los datos de prueba se siembran automáticamente en memoria cuando arranca el API. Tienes 3 leads de ejemplo para mover por los estados.

4.2 Reglas de seguridad de los agentes

La capa de IA tiene tres reglas duras:

  1. Un agente nunca emite SQL ni toca Prisma. Solo invoca tools registradas. Si un prompt es comprometido, el daño se limita a las tools concedidas.
  2. Un agente nunca puede hacer más que quien lo invoca. Sus permisos son la intersección entre los permisos del agente y los del usuario.
  3. Acciones de gasto o publicación siempre requieren aprobación humana. Publicar campañas, cambiar presupuesto y publicar contenido pasan por una bandeja de aprobaciones.

4.3 Cómo se ejecuta una tarea de IA

  1. Orquestador recibe la petición (p. ej. "investiga este nicho").
  2. Clasifica la petición y crea un plan con pasos dependientes.
  3. Delega cada paso al agente especializado. Los permisos heredados son la intersección, nunca más.
  4. El ModelRouter elige modelo local o remoto según clase de tarea, presupuesto y criticidad.
  5. El ToolRegistry valida permiso, input schema, rate limit y, si es necesario, aprobación humana.
  6. El resultado valida contra un output schema. Si pide gastar dinero o publicar, se convierte en una aprobación pendiente.

4.4 Cómo leer una recomendación de IA

Cuando un agente propone algo, verás cuatro campos:

  • WHAT: qué detectó o propone.
  • WHY: evidencia que lo soporta.
  • CONFIDENCE: número del 0 al 100. Por debajo de 70 se marca como dato insuficiente.
  • ACTION: qué puede hacer el sistema si apruebas.

Hoy en la pantalla de IA y en Inicio ves recomendaciones de demostración con badge Demo. No provienen de modelos reales todavía.

6. Desde qué punto partes como usuario

Tu punto de partida práctico es este:

  1. Valida que todo compila y los tests pasan:
    2. corepack pnpm typecheck
corepack pnpm test
corepack pnpm build
  2. Levanta API y web.
  3. Entra en modo demostración y navega por las 7 áreas para validar que la estructura visual te hace sentido.
  4. Prueba el flujo real de leads: ve a /sales o /leads, cambia estados y registra respuestas.
  5. Revisa las decisiones arquitectónicas en docs/decisions.md, docs/roadmap.md y docs/ai-agents.md antes de decidir el siguiente feature.

✅ Recomendación inmediata

El siguiente paso lógico es conectar Postgres + Prisma para persistir leads y usuarios. Eso desbloquea el login real y convierte la demo visual en datos reales. Mientras tanto, el in-memory repository te permite iterar en la API sin depender de Docker en el portátil corporativo.
